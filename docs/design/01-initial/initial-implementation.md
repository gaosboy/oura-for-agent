# 首期实现设计：授权、数据库与同步

## 目标和边界

提供可供脚本和未来 Skill 调用的本地应用：OAuth 授权、每个 Oura 账号独立的 SQLite 数据库，以及按类型和时间范围同步与从起始时间全量同步。首期提供命令行入口；辅助网页和后台定时服务不在本次范围。

## 结构与选择

采用 Python 标准库实现 CLI、HTTP 和 SQLite，减少部署依赖；Link 负责 OAuth、API 请求与分页，Core 负责本地模型、持久化和同步编排，Action 提供命令行与可复用调用接口。相较于直接存储原始响应，本设计使用独立的记录标识、类型、时间和同步状态模型，并保留完整源数据以避免未知字段丢失；各类型的详细领域字段可渐进扩展。相较于直接创建服务进程，CLI 先满足脚本调用，接口保留扩展空间。

## 授权和账号

通过浏览器完成 OAuth 授权码流程，校验 state，使用配置的 client ID、client secret 和已注册的回调地址交换令牌。用 personal_info 的稳定用户标识区分账号，创建独立数据库；令牌和过期时间持久保存于该账号的受限权限文件，并支持刷新。凭据由环境变量或本地配置提供，不写入仓库或日志。身份获取或授权失败时不创建不确定归属的账号数据库。

## 数据和同步

SQLite 建立版本表、账号信息、统一健康记录及同步运行状态。记录按数据类型和上游稳定标识幂等更新，并保留源字段；无稳定 ID 的类型需按其文档定义可靠的自然键，无法确定时明确报错而非静默覆盖。每种类型有显式适配器，负责请求参数、时间语义和映射。

基础同步接受账号、一个或多个数据类型、起止日期；按接口使用日期或带时区的日期时间参数，处理分页和限流，逐类型报告结果。个人信息和设备配置没有日期过滤，按完整快照获取。全量同步接受账号和起始日期，结束边界为执行时当前时间，调用基础同步覆盖所有可读取的数据类型。权限不足、订阅限制或单项失败须明确列出，不能报告为全部成功。增量同步不假设缺失记录即已删除。

## 验证

以离线模拟服务和临时数据库测试授权 state、令牌保存与刷新、账号隔离、日期参数、分页、重复同步、错误和部分失败；测试无需真实健康数据。记录配置、运行和测试命令。真实 Oura 联调需要用户自己的应用凭据和授权账号。
