# 报告模块设计：运动趋势

## 目标

新增报告操作：依据当前激活账号、报告类型和参数读取本地数据，通过模板生成独立报告文件。首次报告为离线可打开的 HTML 运动趋势报告。报告只读取已同步数据，不触发 Oura 同步。

## 目录和调用

- `oura_app/action/operations/report.py`：报告生成操作及结果，CLI 仅调用操作层。
- `oura_app/core/record/`：提供适合报告的完整数据读取，不能依赖当前默认 1000 条的截断结果；采用分页读取或明确检测截断。
- `oura_app/resource/report_templates/`：随应用分发的报告模板及其版本资源。
- `<数据目录的父目录>/reports/`：报告产物；报告目录以私有权限创建，项目根目录下的报告由 `.gitignore` 保护，不纳入版本库。模板与产物目录分开。

操作接口建议 `generate_report(report_type, start, end, force=False)`，使用当前激活账号。CLI 建议 `python -m oura_app.action report activity-trend --start YYYY-MM-DD --end YYYY-MM-DD [--force]`，以 JSON 返回文件路径和是否复用缓存。日期均为包含起止日的业务日期；参数无效或没有激活账号时明确报错。

## 缓存与文件安全

文件名使用参数的 SHA-256 和模板名称的 SHA-256，均基于确定性 UTF-8 编码，格式 `<参数哈希>-<模板名哈希>.html`。参数规范化后包含账号 ID、报告类型、起止日期和影响输出的其他选项；`force` 是执行选项，不参与哈希。同一参数和模板名的已有文件直接返回，不再读取数据；`--force` 重新读取数据并覆盖。模板内容或本地数据变化不会自动使缓存失效，使用强制刷新更新；如需内容版本自动失效，需另行调整约定。

报告包含敏感健康数据，目录和新文件只允许当前用户访问。使用报告目录内的临时文件、原子替换保证写入失败不破坏原报告；严格限制模板名称为已注册类型，避免路径穿越。并发强制生成同一报告时以最后完成的完整文件为准。输出为自包含 HTML，不依赖 CDN 或外部脚本，所有来自数据的文本均做 HTML 转义；不把敏感数据写日志。

## 运动趋势模板

读取区间内已同步的 `daily_activity` 和 `workout`。以本地 `day` 为业务日，保留缺失数据的含义，不把未同步日期视为零运动。图表和汇总提供：

1. 记录覆盖：有活动日报的天数、训练记录数和日期范围；无数据或部分覆盖时显示明确提示。
2. 每日步数趋势及区间平均：仅对有步数记录的日期计算；图表缺失日期留空。
3. 每日中等与高强度活动时长：使用日报的 `medium_activity_time`、`high_activity_time`，单位由秒转换为分钟；以每日堆叠图展示，不与 workout 记录相加，避免重复计算。
4. 训练记录：按 Oura 训练开始与结束时间计算有效时长，展示次数、活动类型分布与列表；异常或缺失时间不计入时长，并注明数量。按上游业务日归属，不擅自拆分跨日训练。
5. 每周活动参考：以周一至周日分组，分别展示中等与高强度分钟数、记录覆盖天数及是否为完整周；仅作为描述性参考，不将日报中的活动自动认定为符合 WHO 定义的有氧运动，也不据此判断是否达标。缺失天数标记为未知。

页面附简短依据：WHO 建议成年人每周进行 150–300 分钟中等强度有氧活动或 75–150 分钟高强度活动，并每周至少两天进行肌肉强化活动；个人情况不同，Oura 数据不能替代医疗建议。链接 https://www.who.int/europe/news-room/fact-sheets/item/everyday-actions-for-better-health-who-recommendations 。报告不作疾病诊断、风险分级、训练处方或基于缺失数据的健康结论。

## 验证

使用合成数据与临时目录测试：相同参数缓存命中、强制刷新、跨账号隔离、失败时原文件不变、模板名安全、字段转义和离线生成；验证超过 1000 条记录时完整读取，缺失/异常数据、跨日和不完整周的统计。CLI 测试校验参数及输出路径。报告不使用真实健康数据作为测试夹具。
